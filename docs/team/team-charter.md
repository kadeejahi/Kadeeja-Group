## 4. Communication Agreements
* **Primary Channel:** Imessages for daily async chat; Google Meet / Zoom for live meetings.
* **Core Working Hours:** We assign tasks, complete our task asynchronously and meet on Monday evenings to discuss.
* **Expected Response Time:** Within **12 hours** on weekdays, and **4 hours** on weekends or close to project milestones.
* **Absence Policy:** If a member cannot complete a task due to illness or exams, they must notify the group at least **24 hours** in advance so work can be reallocated.

---

## 5. Development & Engineering Standards
* **Tech Stack:** Python 3.11+, Git/GitHub, and *[insert specific frameworks like Flask, Django, CustomTkinter, etc.]*.
* **Code Style:** We follow the **PEP 8** style guide. Code must be cleanly formatted and include docstrings for major functions.
* **Branching Strategy:** 
  * Never commit directly to `main`.
  * Create a branch named `feature/your-name-feature-description`.
  * Pull Requests (PRs) require at least **one peer review** and approval before merging.
* **Testing Requirement:** Every feature must include basic unit tests using `pytest` to prevent breaking existing code.

---

## 6. Meeting Schedule & Rhythms
* **Weekly Sync:** Every Monday at 8:30 PM CST (30 minutes) – Discuss progress, blockages, and assign tasks for the week.
* **Updates:** Live updates can be posted within the group message, if need be. 
---

## 7. Conflict Resolution Path
1. **Direct Communication:** Address the issue politely with the team member directly to clarify misunderstandings.
2. **Team Vote:** Bring persistent disagreements (e.g., technical direction or feature scope) to a team sync for an open vote.
3. **Instructor Escalation:** If a member stops contributing or communicating completely, the team will document the timeline and consult the course instructor/TA.
